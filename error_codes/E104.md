The body of a generic function constrains a type parameter to a concrete type (or to another type parameter), so the definition does not type-check for ALL instantiations.

For example, the following is invalid because the body only works when `T` is `Int<32>`:
  def add(a: Int<32>, b: Int<32>) -> Int<32> { return a + b; }
  def g<T>(x: T) -> Int<32> { return add(x, 1); }

Binding one parameter to another is likewise invalid (`T := U`), since the body must be parametric in each distinct parameter:
  def f<T, U>(x: T, y: U) -> U { return x; }

A generic definition must be valid for every type argument; a body that forces `T = Int<32>` would make `g<Bool>` ill-typed.  Rust (rigid `TyKind::Param`), GHC and OCaml (skolems) all reject such definitions at definition time.

Fix: change the signature so the constraint is explicit (e.g. a where-clause), or make the body parametric in `T`.
