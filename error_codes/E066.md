An or-pattern (`pattern1 | pattern2`) refines the same enum type parameter to DIFFERENT types in different alternatives.

For example, the following is invalid because `Add` refines `T == Int<32>` while `Eq` refines `T == Bool`:
  type Expr<T> = enum { Add(...) when T == Int<32>, Eq(...) when T == Bool }
  match e { Add(_, _) | Eq(_, _) => ... }

A branch guarded by a disjunction may only assume facts true in ALL alternatives. Conflicting refinements are a contradiction.

Fix: split the or-pattern into separate match arms, or make the alternatives refine the type parameter consistently.
